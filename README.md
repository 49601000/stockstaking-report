# 棚卸照合デスク

## 起動

プロジェクトのルートで、初回は `npm install`、`npm run build` を実行します。以降は `npm start` で起動して http://localhost:4173 を開いてください。
同梱の `public/index.html` を直接開いてファイル選択で使用することもできます（ローカルデータの自動読込・Drive接続はサーバー起動時のみ）。ビルド済みの `dist/app.js` が必要です。

## ディレクトリ構成

```text
棚卸マッピングツール/
├─ data/
│  └─ README.md                    ローカル実データの置き方
├─ src/
│  ├─ app.js                       画面操作・ファイル取込・Excel出力
│  ├─ core/reconciliation.js       データ解析・照合の判定処理
│  └─ integrations/google-drive/
│     ├─ api.js                    Driveの一覧取得・ダウンロード
│     └─ ui.js                     Google接続・選択画面
├─ public/
│  ├─ index.html                   画面のHTML
│  └─ styles/main.css              画面のスタイル
├─ config/samples.json             公開用の空サンプル一覧
├─ scripts/server.js               ローカルサーバー
├─ tests/
│  ├─ unit/                        照合・Drive APIの自動テスト
│  ├─ browser/                     実ブラウザの操作テスト
│  └─ helpers/                     テスト共通のデータ読込
├─ dist/app.js                     ビルドで生成するブラウザ用JS
├─ package.json                    起動・ビルド・テストの設定
├─ package-lock.json               依存ライブラリの固定情報
└─ README.md
```

実データは `data/local/` 直下へまとめて置きます。`data/local/` はGit管理対象外です。在庫全体、matoi、nicomeなどでディレクトリを分けず、読み込むファイルを同じフォルダに置いてください。ファイルを置くだけでの自動取込は行いません。画面からファイル選択・ドラッグ＆ドロップするか、Driveから直接取り込んでください。ブラウザのダウンロード先も自動変更しません。

「ローカルデータを読み込む」ボタンは、起動時に `config/samples.local.json` があればそれを読みます。このファイルもGit管理対象外です。公開用の `config/samples.json` は空のままにしてください。`dist/app.js` は直接編集せず、`src/` を変更したあと `npm run build` で更新してください。ブラウザテストや出力物は `output/` に保存しますが、`output/` もGit管理対象外です。

## 操作

1. 在庫の `棚卸データ_…js` と店舗ごとの `…result….json` をまとめて読み込みます。
2. 比較する在庫を選びます。初期値は `exportedAt` が最新の在庫です。複数在庫は合算しません。
3. 店舗、分類、確認状態、要確認、未完了で絞り込みます。商品詳細で確認理由・対応メモ・照合完了を記録できます。
4. 「Excelを出力」で全商品、要確認、店舗別集計、ブランドメモ、在庫明細履歴、棚卸明細履歴、取込元、判定ルールの8シートを保存します。画面の絞り込みは出力を制限しません。
5. 「全店舗をCSV出力」で、読み込んだ両店舗の全商品を1つの一覧に保存します。Excelの「商品照合」と同じ列（店舗・商品ID・在庫数・棚卸状態・確認理由・対応メモ・照合完了など）を出力します。画面の店舗・検索・状態などの絞り込みに関係なく全件が対象です。Excelで日本語を開きやすいUTF-8（BOM付き）形式で、メモ内の改行・カンマ・引用符も保持します。
6. 対応記録はブラウザに保存します。バックアップ・別PCへの移行にはJSON保存と復元を使います。元の在庫・棚卸ファイルは再読込が必要です。

## 判定

- 照合キーは「店舗＋商品ID」。ブランド・モデル・カラーの近似一致は使いません。
- ①棚卸側のみ：棚卸元在庫にあり選択在庫にない。販売、移動、修正など理由の確認が必要。
- ②両方：両時点の在庫に存在。棚卸の現物確認状態は独立して表示。
- ③最新在庫側のみ：全ブランドの棚卸結果に記録がなく選択在庫にある。入荷と断定しません。
- 棚卸結果のない店舗、一部ブランドの棚卸、比較元より古い在庫の追加商品は比較対象外。
- 棚卸結果は店舗ごとに `generatedAt` が最新のファイル全体を採用。旧版は履歴に残し、自動で補完しません。日時が同じ場合はファイル名順で選択します。
- ID重複は1行にまとめ、双方の明細件数を表示して警告。代表属性は先頭明細で、全明細はExcelの履歴シートに保存。
- 別店舗の同IDは移動候補として提示。IDが全店舗共通か未確認のため自動で統合しません。
- ブランドメモは商品がなくても専用一覧・Excelに残します。
- 照合対応は比較した在庫ファイル・日時と棚卸結果ファイル・日時に紐づきます。日付の違う在庫には自動転用しません。
- 日時は日本時間。元データと出力は外部へ送信しません。JS入力はJSON部分のみ解析し、コードとして実行しません。

## Google Driveからの取込

画面の「Google Driveから選択して取り込む」を開き、初回設定にDriveフォルダIDとOAuthクライアントIDを入力して「Googleで接続」すると、そのフォルダ直下のJS・JSONを一覧表示します。種類・名前で絞り込み、チェックして直接取り込めます。個別の「DL」は元ファイルを保存します。サブフォルダ・Googleドキュメント・ショートカットは対象外、1ファイル20MBまでです。

### 初回設定

1. [Google Cloud Console](https://console.cloud.google.com/)でプロジェクトを作成または選択し、Google Drive APIを有効化。
2. Google Auth Platformでブランディング・対象ユーザー・同意画面を設定。外部・テスト運用の場合は利用アカウントをテストユーザーに追加。
3. データアクセスで `https://www.googleapis.com/auth/drive.readonly` を設定。これはDrive全体の読み取り権限です。アプリは指定フォルダの一覧と選択ファイルのダウンロードにだけ利用し、書き込み権限は要求しません。一般公開する場合はGoogleの検証要件を確認してください。
4. 種類「ウェブアプリケーション」のOAuthクライアントIDを作成。承認済みのJavaScript生成元に `http://localhost` と `http://localhost:4173` を追加（パスは付けない）。リダイレクトURIとクライアントシークレットはこの構成では使いません。
5. `npm start` で起動して **http://localhost:4173** を開く。Driveパネルの初回設定欄へDriveフォルダIDとOAuthクライアントIDを入力し、「Googleで接続」。フォルダの共有先アカウントを選んで読取アクセスを許可。

HTMLの直接起動（`file://`）ではGoogle認証は利用できません。ホスト・ポートを変更した場合は、その生成元をGoogle Cloudにも登録してください。画面内のDriveフォルダIDとクライアントIDはブラウザに保存しますが、アクセストークンはメモリだけに保持し、ページ更新・接続終了で破棄します。期限切れは再接続してください。「接続終了」はアプリ内の接続を終了する操作で、Google側に残った許可の取り消しやGoogleアカウントのログアウトではありません。

DriveのファイルはブラウザからGoogle APIを通して直接取得し、ローカルの照合処理に渡します。アプリのGoogle認証とCodexのDrive接続は別です。Google認証・APIの利用時はGoogleと通信しますが、照合結果をアップロードする処理はありません。

一覧はページをすべて取得し、選択取込前にファイルの所属フォルダとダウンロード権限を再確認します。一部だけ失敗した場合は成功分を保持して失敗を表示。同名ファイルは上書きせず、既存の取込を削除してから取り込み直します。Drive更新日時で照合の最新版を決めることはせず、従来どおりJSON内部の日時を使います。

公式資料：[クライアントID設定](https://developers.google.com/identity/oauth2/web/guides/get-google-api-clientid)、[ブラウザ用トークンモデル](https://developers.google.com/identity/oauth2/web/guides/use-token-model)、[Driveのダウンロード](https://developers.google.com/workspace/drive/api/guides/manage-downloads)。

実棚数量を追加・訂正する機能はありません。元データの各商品IDを1明細として扱います。メモ内の「5本」等は文章として保持し、在庫数量に自動反映しません。

## 検証

`npm test` で分類、時点逆転、対象外、重複、店舗移動候補、過去版、保留状態、メモ、実データ件数を検証します。

Driveのページ取得・権限・ファイル移動・認証エラーもAPI応答を模擬して検証します。`npm start` 後の `npm run test:browser` はEdgeの非表示ブラウザで、既存画面とDrive取込・DLを検証します。Drive認証・APIはこのテストでは模擬応答です。実際のアカウントのログインとAPI通信は、クライアントID設定後に別途確認してください。
